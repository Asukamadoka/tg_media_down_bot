# M9.4: download priority

> Drafted by Cowork, 2026-10-03. Baseline: 1594fd5 (M9.3). Bot UI text is Chinese; code, docs and commits are English.

Saki wants a "download this first" control on top of M9.3's start/pause/stop.

## A. Priority model

1. **Levels.** Each task (file) has `priority`, an int: `0` normal (default), `1` high, `2` top (置顶).
   - Each plan also has a priority, used as a default for its tasks.
   - Store both persistently: the plan body for plans, the task state for tasks.
2. **Order.** Queued tasks start in order of `(-priority, plan created_at, item index)`. This order holds across every running plan, not only within one.
3. **Bandwidth share.** Inside the shared `OUTBOUND_MAX_TOTAL_CONNECTIONS` pool, connection grants are weighted by priority (normal 1 : high 2 : top 4), applied when connections free up.
   - A top task may take connections back from normal tasks. This is a soft pre-emption: a normal task drops connections at its next range boundary, never mid-range.
   - Tasks keep their `.part` progress.
4. **No starvation.** Normal tasks always keep at least 1 connection while running. A paused task holds none (M9.3).

## B. Controls

1. **Progress message**, per task line: add `优先` (cycles normal → high → top → normal), shown as a ⬆ marker on the line.
   - Plan-level: `整组优先`.
2. **CLI**: `wms task priority <plan>:<n> normal|high|top` and `wms plan priority <plan> normal|high|top`.
   - Same request table as the other task controls.
3. **NL**: 「先下 X」「优先下载 X」「X 置顶」 → set the priority of matching tasks in running or pending plans. This never creates a new download plan, the same guard as M9.2's remarks.
   - If nothing matches, reply 「没有找到正在排队或下载的 X」.
4. **`/downloads`** shows queued tasks in their actual start order.

## C. Tests

- Order across plans.
- Weighted grants.
- Soft pre-emption only at range boundaries.
- Minimum 1 connection.
- Cycle button.
- CLI requests picked up.
- NL phrases set priority, and none of them creates a plan.
- Persistence across a restart.

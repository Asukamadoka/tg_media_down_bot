## A. Node selection

1. **mihomo layout.** Cowork applies the config; the bot only relies on these names existing.
   - `AUTO-LATENCY`: url-test over `main`, info entries excluded. This is "lowest latency".
   - `FAST`: a `select` over `main` nodes. **The bot sets it** to the node with the best measured throughput.
   - `PROXY` (general access): `select [AUTO-LATENCY, FAST, <each node>]`, default `AUTO-LATENCY`.
   - `TG`: `fallback [TG-PICK, AUTO-LATENCY]`. `TG-PICK` is a `select [FAST, AUTO-LATENCY, <each node>]` set by the bot, default `FAST`, because Telegram media is the bot's bulk download. Fallback keeps Telegram up if the picked node dies.
   - `PROBE`: `select [DIRECT, <each node>]`, reachable only through listener `probe` (mixed, `127.0.0.1:7899`) via the top rule `IN-NAME,probe,PROBE`.
2. **Throughput probe** (`tgmd/traffic/probe.py`).
   - **When.** Every `PROXY_PROBE_HOURS` (default 6) and on demand.
   - **Per node, one after another:**
     - Set `PROBE` to the node.
     - Latency: `GET /proxies/<node>/delay?url=https://www.gstatic.com/generate_204&timeout=5000`.
     - Download: fetch `PROXY_PROBE_URL` (default `https://speed.cloudflare.com/__down?bytes=8000000`) through `http://127.0.0.1:7899`, capped at 8 MB or 10 s.
     - Upload: POST 2 MB to `PROXY_PROBE_UP_URL` (default `https://speed.cloudflare.com/__up`).
   - **Skips.** Skip nodes priced above `PROXY_PROBE_MAX_PRICE` (default 0.09), info entries, and dead nodes.
   - **Cost.** A run must stay under `PROXY_PROBE_MAX_MB` (default 150). The meter counts probe bytes as category `probe`; add it to the classifier through the listener name in `metadata.inboundName`.
   - **Result.** Store per-node `latency_ms`, `down_mbps`, `up_mbps`, `price`, `alive` and `tested_at` in the traffic DB.
   - **Picking.** In auto-speed mode, set `FAST` to the best node by download speed. Among nodes within 15% of the best, take the cheapest.
3. **`/proxy` command** (owner only; menu label `节点`).
   - **Shows:**
     - each group (访问 = `PROXY`, 下载/Telegram = `TG-PICK`): its mode, current node, latency, last measured speed and price;
     - the provider's alive count;
     - the last probe time.
   - **Buttons per group:** `自动·延迟最低` `自动·速度最快` `手动选择…`. The last one pages through the alive nodes, showing latency, speed and price.
   - **Also:** `立即测速`, which runs the probe now and reports the result in the same message.
   - **Persistence.** A manual pick sets mode `manual` and stops auto re-picks for that group until the owner switches back to an auto mode. Modes and picks survive restarts (bot DB) and are re-applied to mihomo at start.
4. **Allowed mihomo writes.** Nothing else is allowed. Never `PUT /configs`, never restart anything.
   - `PUT /proxies/{FAST|TG-PICK|PROXY|PROBE}`
   - `DELETE /connections/{id}`, only as in A.5
   - `PUT /providers/rules/direct-auto`, as in B
   - `GET …/delay`
5. **Telegram exit switch safety.**
   - **After changing `TG-PICK` or `FAST` while `TG-PICK=FAST`:** close the existing connections whose chains include `TG`, so Telethon reconnects through one exit only (AuthKeyDuplicatedError guard).
   - **Rate limits.** Automatic switches are at most one per `PROXY_SWITCH_MIN_MINUTES` (default 30). Manual switches are not limited.
   - **Hysteresis.** Do not auto-switch unless the new node is at least 25% faster or the current one is dead.
   - **Gate.** Never switch while the M9 gate shows a Telegram upload in its final part.
6. **Subscription health** (alert only).
   - **Trigger:** the provider refresh fails, or at least 80% of `main` nodes have been dead for 10 minutes.
   - **Alert** (once per incident):
     ```
     代理订阅可能失效（余额不足或已过期）：存活 N/M 个节点。请续费或把新订阅发给 Cowork 更换。
     ```
   - **Recovery:** send a recovery note.
   - **Out of scope:** no account automation of any kind.

## B. Direct-first routing

1. **Candidates.**
   - Hosts that moved more than `DIRECT_CANDIDATE_MB` (default 50) via proxy in the last 24 h, taken from M9's `traffic_host_day`;
   - plus `DIRECT_PROBE_HOSTS` (comma list; default `registry.ollama.ai,ollama.com,r2.cloudflarestorage.com,github.com,objects.githubusercontent.com,pypi.org,files.pythonhosted.org`).
   - **Never** test or route Telegram domains or CIDRs, the subscription host, or LAN.
2. **Test.**
   - Run the test through the probe listener twice: once with `PROBE=DIRECT`, once with `PROBE=AUTO-LATENCY`'s current node.
   - Each run: DNS → TCP → TLS with a verified certificate → `HEAD https://<host>/` (or a configured test URL). A 2xx–4xx answer counts as reachable.
   - Measure throughput only when a test URL is configured for the host (`DIRECT_TEST_URLS`, `host=url` pairs).
   - Direct "works" when TLS is valid, there is no reset or timeout, and latency is no more than 3× the proxy's. When throughput is measured, direct must also reach at least 70% of the proxy's speed or 2 MiB/s.
3. **Apply.**
   - A file rule-provider `direct-auto` (behaviour `domain`, format `text`) is mounted into the bot at `/mihomo-rules/direct-auto.txt`, with the rule `RULE-SET,direct-auto,DIRECT` placed after the LAN rules and before Telegram.
   - The bot writes the file atomically (temp file plus rename), then calls `PUT /providers/rules/direct-auto`.
   - A validator rejects Telegram and the subscription host entries.
4. **Owner control.**
   - `/proxy` → `直连检测` lists the results, with buttons `设为直连` and `保持代理` per host.
   - With `DIRECT_AUTO_APPLY=true` (default false), hosts that pass are added without asking, and the owner gets a note.
   - Applied hosts are re-tested weekly. If direct breaks, alert the owner and offer `恢复代理`.

## C. Faster PikPak → NAS (`pikpak_wms/ops/fetch.py`)

1. **Two links.**
   - Ask `get_download_url` once. Keep `web_content_link` and the `medias` entry with `is_origin=true`.
   - Use the origin link only when its probe shows the same total size and the same SHA-256 of the first 256 KiB as the web link; otherwise log why and use the web link alone.
   - Never use hosts the API did not return. Never change query parameters.
2. **Adaptive connections.**
   - **Start.** Open `OUTBOUND_CONNECTIONS` (default raised to 12) connections.
   - **Rebalance.** After 20 s, compare per-link throughput and move the ranges that have not started to the faster link. Weighted split is fine.
   - **Ramp.** Add 4 connections while aggregate speed rose by more than 15% in the last 20 s, up to `OUTBOUND_MAX_CONNECTIONS` (default 16, hard cap 32).
   - **Back off.** Drop 4 on HTTP 429/503 or repeated resets.
   - **Relinking** (M8.3: 403/410 → new link) re-asks for both links.
3. **Report.** Store per-file `avg_mib_s`, the links used, and the peak connection count in the plan result. Show `平均 X MB/s · 连接 N · 源 web+origin` in the progress message and the final summary.
4. **Bench CLI.** `wms bench-fetch <PikPak path> [--seconds 10] [--connections 1,4,8,16]` reproduces the table above. It prints hosts, never URLs.
5. **Unchanged.** Resume (`.part` and `.part.state`), the M9 direct-cap gate, and the library layout stay as they are.

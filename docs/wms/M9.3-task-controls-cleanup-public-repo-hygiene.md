## A. Per-task controls for multi-file downloads

M9.2 added per-file `取消` and `重试失败的`. Saki wants three explicit controls for every task, in the progress message and through the CLI.

1. **`暂停`.** Stop transferring this file now.
   - Keep its connections' progress in `.part` and `.part.state`.
   - Release its connections to the shared pool, so other files speed up.
   - Status: `已暂停`.
2. **`开始`.** Start a queued file now (it jumps the queue), or resume a paused one from `.part.state`.
   - If `OUTBOUND_PARALLEL_FILES` is already full, the file takes the next free slot ahead of the other queued files.
3. **`终止`.** Stop the file and drop it from this run.
   - Record it as `cancelled` in `downloads`.
   - Follow-up button `删除已下载部分`, which removes the `.part` and `.part.state` only after one more confirm button. Without that confirm the partial file stays and is resumable later.
   - M9.2's `取消` becomes `终止`. Keep the old callback data working for messages already sent.
4. **Layout.** One line per task (file):
   - name, state (`排队中 / 下载中 / 已暂停 / 已完成 / 已跳过 / 失败 / 已终止`), %, MiB/s;
   - buttons on the same line: `开始` or `暂停`, plus `终止`.
   - Plan-level buttons: `全部暂停`, `全部开始`, `重试失败的`.
   - Paged, as M9.2 already does.
5. **CLI** (Cowork uses it on the NAS without Telegram):
   - `wms tasks [--plan N]` lists the tasks and their states;
   - `wms task pause|start|stop <plan>:<n>`;
   - `wms task stop <plan>:<n> --delete-partial --yes`.
   These act on a running bot through the same request-table pattern as M9.2 `ask-probe`; the running bot polls it at most every 5 s.
6. **Running a plan from the CLI.**
   - `wms apply <plan>` for an outbound plan must use the downloader the plan was built with. Today `wms outbound … --downloader local` makes a plan, then `wms apply N` without `--downloader local` only printed links. Store the downloader in the plan body.
   - The CLI path must also write `downloads` rows and honour the controls above.
7. **No signed URLs in logs or output.** The links-only output and error messages printed full signed PikPak URLs (query includes `sign`, `pr`, `userid`, `fileid`).
   - Everywhere outside an explicit `--show-links` print, redact the query to `https://<host>/…?<redacted>`.
   - Exception messages (aiohttp `ClientResponseError` carries the URL) must be redacted before they are logged, stored in plan results, or shown in Telegram.

## C. Public repository hygiene

The repo `Asukamadoka/tg_media_down_bot` stays **public**. Saki: the source may be open, but secrets, addresses, personal information and device parameters must be removed or encrypted.

1. **Audit.** Run gitleaks (full history) plus a custom pattern list over the working tree **and** all history. Write the findings to `docs/security/2026-10-03-public-audit.md`, giving per item: file, first commit, category, and whether it is still in HEAD. **Never print secret values; show a 4-char prefix at most.** Patterns:
   - tokens and keys: Telegram bot tokens, api_hash, PikPak tokens, subscription URLs with `key=`, GitHub tokens;
   - LAN addresses and host names: `10.10.10.x`, `192.168.x`, `*.local`, the NAS model;
   - personal identifiers: e-mail addresses, Telegram user ids and chat ids (for example the cache chat id), real names;
   - device parameters: NAS volume paths with share names, uid/gid choices that identify the NAS, Mac user name and home paths, device names.
2. **Scrub HEAD.**
   - Replace values in docs, briefs, HANDOFF, tests, fixtures and config defaults with placeholders: `<NAS_IP>`, `<MODEL_HOST>`, `<OWNER_ID>`, `<CACHE_CHAT_ID>`, `<NAS_VOLUME>`, `<USER>`.
   - Real values belong only in `.env` on the NAS, which is not in git.
   - Code defaults must not contain any real address or id.
   - Operational notes that need real values do not go in this repo. Saki keeps them in the private `Asukamadoka/skill-builder` hub or the vault. Note in HANDOFF where they moved.
   - Keep docs readable: a placeholder plus one line saying where the real value lives.
3. **Prevent.**
   - Add `.gitleaks.toml` with the custom rules.
   - Add a gitleaks step to CI that fails the build on a finding.
   - Add an optional pre-commit hook config.
   - Document all three in `CONTRIBUTING.md` or in `docs/security/README.md`.
4. **History.** Do **not** rewrite history or force-push. Prepare `docs/security/history-rewrite-plan.md` for Saki's decision:
   - the exact `git filter-repo` replace-text file (patterns only, not values);
   - the force-push steps;
   - what it breaks: commit hashes in docs and HANDOFF, open clones, GHCR image labels;
   - which credentials must be rotated **whether or not** history is rewritten (anything found in public history must be treated as leaked);
   - a note that old public GHCR image layers also contain old files.
5. **Image.** Check the Docker build context (`.dockerignore`) so docs, tests, briefs and `.env*` are not copied into the public image.

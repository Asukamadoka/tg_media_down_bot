# M8.2：Mac 模型评测结论 ＋ 自然语言结果的规范化与安全护栏

> 起草：Cowork（2026-10-01）。执行方：Claude Code。基线：M8.1（`docs/wms/M8.1-index-freshness.md`），可以和 M8.1 一起做。

## 评测结果（NAS → Mac，`eval --backend openai --base-url http://10.10.10.1:11434/v1`）

- 模型：`qwen3:30b-instruct`，即 Qwen3-30B-A3B-Instruct-2507 Q4_K_M，跑在 M5 Pro 64 GB 的 Ollama 上。
- 94 句，处理 88 句（覆盖率 0.936）。判对 52，判错 36，**字面准确率 0.591**。平均每句 **2.6 秒**，延迟达标。
- schema 失败 6 句：
  - 5 句都是 `created_after` 或 `created_before` 写成了 `'today'`；
  - 1 句是跑评测时恰好遇到「every model host is offline」（Mac 短暂没响应）。

## 36 句判错的逐条分析

### 1. 语义等价，但被判错（约 14 句）→ 改评测

| 模型输出 | 期望 | 说明 |
|---|---|---|
| `"2026-09-24"` | `"2026-09-24T00:00:00+08:00"` | 只写日期，不写时间 |
| `"7d"` | `"1w"` | 同一时长的两种写法 |
| `kinds: ["image","video"]` | `kinds: ["video","image"]` | 只是顺序不同 |
| `kinds: ["video"]` 并且列出一串视频扩展名 | 只有 `kinds` | 多写了冗余的扩展名 |

另外几种也属于这一类：

- 「今天」「本月」多写了一个 `created_before`，值是下一天或下个月的 0 点，不影响结果；
- delete、trash、organize 这类 intent 多带了无意义的 `action_args.dest`，比如 `/Trash`、`/Recycle Bin`。

### 2. 小瑕疵（约 3 句）

- 「以 sample 开头」被写成 `name_contains`，丢了「开头」的约束；
- 「字幕」只给了 `srt`，漏了 `ass`；
- 「去年」的上界写成 `2025-12-31T23:59:59`，意思没错，但写法不规范。

### 3. 真错，其中有危险的（约 19 句）

- **时间方向写反**，最危险：
  - 「删除 /Temp 里超过 7 天的文件」→ `created_after: 7d`，会删掉**最近 7 天**的文件；
  - 「超过半年的文件归档」「2026 年 1 月 1 日之前的文件」同样写反；
  - 「三个月前」「60 天前」被写成一个区间，或者乱填。
- **尺寸写成 0**：`min_size: 0` 和 `max_size: 0` 一起出现，`max_size: 0` 会让结果只剩空文件。
- **凭空加条件**：「清理名字含广告的文件」被加上了 `created_after`、`created_before`；「/Cosplay/合集」被塞满了随意的 filter。
- **该问却没问**：「你好」→ list；「网盘还剩多少空间」→ big_report；「清空回收站」→ trash。
- **不该问却问了**：
  - 「整理一下 Telegram」「Pack From Shared 整理一下」应该是 organize_inbox；
  - 「把大文件单独放一起」应该是 `organize_tree part=big`。
- 其他：「上个月」写成 `1m`；「列出昨天下载的」写成 `1d`、`2d`。

**结论**：按语义等价重新计分，大约是 66/88 ≈ 75%。修好 `'today'` 之后大约 78%，还没到 80% 的目标。延迟没问题。问题主要集中在两类：**时间方向**和**乱填字段**。这两类都适合用代码兜底，不必换更大的模型。

## 修改要求

### A. 评测改成语义等价比较（`pikpak_wms/nl/eval.py`）

1. 比较之前，期望和实际两边都过一次规范化，然后再比：
   - 日期统一成 `+08:00` 的 ISO 格式；
   - 时长统一成天数（1w=7d，1m=30d），允许 ±1 天的误差；
   - 列表排序后比较；
   - 如果 `kinds` 已经完全覆盖某些扩展名，就去掉这些扩展名；
   - 只对 move、copy、archive、download 比较 `action_args.dest`，其他 intent 忽略这个字段；
   - 「今天」「本月」这类说法多出来的、等于下一个自然边界的 `created_before`，视为等价。
2. 评测句里的日期不要写死成 2026-09-24，改成模板形式，比如 `{today}`、`{yesterday}`、`{month_start}`，运行时按 `--now`（默认当前时间，Asia/Shanghai）展开。
3. 输出三类计数：`right`、`equivalent`、`wrong`，另外单独统计 **`dangerous`**：删除类或归档类 intent 的时间方向写反，或者 `max_size` 为 0。

### B. 翻译结果的规范化（M8 规范化再扩一层，放在 schema 校验之前）

1. `min_size` 和 `max_size` 为 0 时，当作 null。
2. 只写日期的值（`YYYY-MM-DD`），补成当天 `00:00+08:00`。
3. `today`、`yesterday`、`今天`、`昨天`、`本周`、`本月`、`上个月`、`去年`：换算成具体的边界日期。这一条和 M8.1 §C 一起做，别写两份。
4. intent 是 delete、trash、list、count、organize_*、big_report 时，丢掉 `action_args.dest`，也不在计划里展示。
5. 给出了 `kinds` 的同时又给了 `extensions`，并且这些扩展名全部属于 `kinds`：丢掉 `extensions`，保留 `kinds`，避免漏掉 ass、m2ts 这类格式。

### C. 时间方向的双保险

1. **规则层先判断方向**：原句里出现「之前」「以前」「前的」「超过 N 天」「N 天前」「早于」「older than」，而且句子里没有「最近」「以来」「之内」「内」「以后」，就断定时间条件是 `created_before`。
   - 模型给出的是 `created_after` 时，把它换成 `created_before`，并在计划里标注「已按原句更正时间方向」。
   - 反过来，出现「最近」「之内」「以来」「今天」「本周」时，只允许 `created_after`。
2. **delete、trash 必须把时间写成白话**：计划的第一行用中文写出时间条件，比如「创建于 7 天以前（早于 09-24 00:00）」或「最近 7 天内创建」。用户确认时一眼就能看出方向对不对。
3. **单独的时长字面量都按「多少天以前」理解**：同时出现了 `created_after: Nd` 和 `created_before: Nd`，并且 N 相同，说明模型没理解，改成回复 `clarify`。

### D. 该问的要问，该认的要认

- 规则层补齐这些说法：「整理一下 X」「X 整理一下」，X 是入口目录（Telegram、Pack From Shared）→ organize_inbox，路径就是 X。「大文件 / 大目录 单独放 / 集中」→ organize_tree，参数 `part=big`。这几句不应该交给模型。
- 下面三类一律回复 `reject` 或 `clarify`，并且优先在规则层拦截：
  - 问候、闲聊；
  - 查询网盘空间和配额（现在不支持）。以后要做，就做成 `/quota`；
  - 「清空回收站」：PikPak 回收站属于永久删除，按安全红线，bot 不执行，回复「请在 PikPak 里手动清空」。
- few-shot 再加 4 条：
  - 两条时间方向的反例：「超过 7 天」→ `created_before: 7d`；「最近 7 天」→ `created_after: 7d`；
  - 一条「上个月」；
  - 一条「以 X 开头」→ `name_regex: ^X`。

### E. 主机在线探测的抖动

评测时有一句碰上「every model host is offline」。M8 的离线缓存是 60 秒，一次探测超时就会让这 60 秒里的请求全部落空。改成这样：

- 生成请求失败之后，立刻重新探测一次；
- 连续失败 2 次，才判定离线。

### F. 验收

- 单元测试：
  - B 的五条规范化各一条测试；
  - C 的方向更正：「超过 7 天」「最近 7 天」「2026 年 1 月 1 日之前」；
  - D 的规则命中。
- Cowork 在 NAS 上重跑 Mac 评测。目标：
  - 等价准确率 ≥ 85%；
  - `dangerous` = 0；
  - 平均每句 ≤ 5 秒。
